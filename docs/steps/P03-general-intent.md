# P03：从特定场景脚本转向可迁移的决策原则

日期：2026-10-22。[完整文本：前后提示词与待测场景](P03-readable.md)。本轮是基于作者审查意见的提示词修订，不包含新增真实模型实验；不能沿用P01/P02的回答来证明新版本效果。

## 作者指出的问题

原提示规定面对“明天要交周报，你帮我留意一下”先关照完成情况。这把作者认可的一条样本回答升级成了强制的理解顺序。用户也可能只想收到提醒，固定先问进度同样可能误解需求。

纠错记录：[2026-10-22] 提示词对测试场景过拟合。context：主代理将单个正向反馈写成生产提示中的场景专属决策。action：删除固定周报入口，以解释差异是否影响行动为澄清条件；具体例子作为独立评价场景，不能作为唯一正确答案或保证迁移的证据。

作者的“秘书”是理解方式的比喻，核心目标仍是第二大脑：理解需求、完成任务，并帮助发现尚未意识到的重要问题。不能把它缩成只做提醒，也不能用“思考伙伴”替用户定义真正目标。

## 本次修改与取舍

1. 身份改为帮助理解问题、判断和完成任务的第二大脑，保留真实结果和权限边界。
2. 删除“周报先问进度”的固定规定，改为多种合理解释会导致明显不同的行动时澄清关键歧义；信息充分则推进，非关键小不确定性可说明假设。
3. 区分直接回答、主动补位、共同分析三种响应方式，按情境选择，不按A到C固定升级。
4. 主动提出重要问题必须说明与当前目标的关系、依据和影响；信息不足时提出假设并核对，不编造用户背景或断言其真实动机。
5. 尊重明确范围，不以主动性为由拖延交付、反复提问或制造新任务。删去持久化规则中的周报式承接例句，保留不能虚报保存的通用边界。

候选原则是：明确结果时直接交付；有相关事实依据时主动补位；方向、目标或取舍未清时共同分析。三者可以在对话中切换，不是一轮都要做完的流程。A也可能是当下最合适的帮助，C不能成为每个请求都要先分析动机的理由。

具体工具的ID、参数、错误语义是接口契约，和规定某种自然语言请求必须怎样理解不是同一种特化。本轮只处理后者，不顺便迁移工具说明、改Runtime或增加新工具。

## 完整内容与效果状态

阅读版保留本轮前后系统提示全文、区别及六类跨场景待测输入。每个待测场景明确标注“模型回答：本轮未调用”，不编造结果，也不把主代理的理想回答当成模型实际表现。

尚未证明新版本能在学习、出行、项目和写作等场景稳定选择合适方式。提示词更通用也可能带来边界模糊、过度分析、遗漏主动建议等新问题。后续应该使用固定多轮对话及未写进提示的保留场景，比较澄清必要性、行动选择、事实依据、范围遵守、任务完成和调用成本；不以“更像某条示范回复”作为唯一评分。
