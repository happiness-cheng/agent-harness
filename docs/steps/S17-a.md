## 配置与真实HTTP路径

OpenAISettings固定model=gpt-6.1-sol、reasoning_effort=high，默认max_requests=3、max_output_tokens=4096、timeout_seconds=60。后者是HTTPX每I/O阶段超时，不是整次任务墙钟上限；跨任务总预算仍留S19。SecretStr认证字段不出现在普通repr/model_dump中。

from_credentials_file必须显式传路径，支持UTF-8 BOM，只支持已约定的openai_api_key/deepseek_api_key键，仅读取OpenAI字段用于认证；未知base_url等配置拒绝而非悄悄忽略。坏文件/重复JSON键/缺key/非法头字符统一脱敏，不输出文件正文；不修改用户密钥文件。

客户端使用固定https://api.openai.com/v1/responses；默认TLS校验保留，follow_redirects=False，trust_env=False，不读环境代理或默认凭据。Header仅作认证，模型input里没有key。HTTP非200只提供http_状态码，不保留错误正文，故诊断精度有限；网络异常固定network_error，不把可能含认证请求的异常字符串传入trace。没有自动重试；失败请求也计入实例上限。

真实请求体的实际代码：

```python
body = {
    "model": self._settings.model, "input": build_input(messages, model=self._settings.model),
    "tools": build_tools(tools), "parallel_tool_calls": False,
    "include": ["reasoning.encrypted_content"],
    "reasoning": {"effort": self._settings.reasoning_effort, "summary": "auto"},
    "store": False, "stream": False,
    "max_output_tokens": self._settings.max_output_tokens,
}
```

parallel_tool_calls=False表达请求偏好，Runtime仍保留串行多调用处理。store=false关闭Responses应用状态存储，不等于提供商所有日志零留存承诺；不用previous_response_id把本地会话隐式绑定成服务端会话。

HTTP流读取有4MiB本地响应缓冲上限，检查后才追加；无论协议成功或错误都由with关闭响应，模型对象也支持with/close。可类比C++作用域资源管理，不依赖Python析构时机。运行时收到异常仍按既有model_call_failed等状态返回，不伪称业务完成。

## 结束原因与原生工具协议

输出item.id与工具call_id不同。适配器把call_id映射到ToolCall.id，Runtime实际执行本地注册工具，tool消息编码成同call_id的function_call_output。arguments严格解析为JSON对象，拒绝重复键/非有限值；未知远端输出工具类型拒绝，不自动执行提供商内建能力。

status的实际判定片段：

```python
if status == "incomplete":
    reason = raw["incomplete_details"]["reason"]
    finish = {"max_output_tokens": "length", "content_filter": "refusal"}.get(reason, "error")
else:
    finish = "refusal" if refused else "tool_calls" if calls else "stop"
```

此前已拒绝未知状态；failed/cancelled/queued/in_progress映射error，不把非终态文字当回答。completed响应中如果条目仍incomplete也拒绝。只有完整function_call才生成可执行请求；截断即使带半截arguments也不执行。content_filter映射refusal是本适配器的保守结束分类，不表示模型一定主动拒绝。

文本、可用summary与原生状态分开。完整stop/tool_calls响应保存全部原生output，截断/拒绝/失败不回放不完整调用；可见片段仍按原有Runtime状态保存，不能据此声称完整推理恢复。

## 为什么新增provider_state

仅保存role/content/工具参数会丢失reasoning、加密状态、原生ID等必要协议事实。给Message和ModelResponse加可选ProviderState，旧记录缺省None；只有assistant可携带，原生输出不进入普通repr。实际模型如下：

```python
class ProviderState(BaseModel):
    """提供商原生输出，用于协议回传；加密状态不解密或作为摘要展示。"""

    model_config = ConfigDict(strict=True, extra="forbid", allow_inf_nan=False)
    provider: Literal["openai.responses", "deepseek.responses"]
    model: str = Field(min_length=1, pattern=r"\S")
    response_model: str = Field(min_length=1, pattern=r"\S")
    output: list[dict[str, JsonValue]] = Field(repr=False)
```

model记录请求ID，response_model保留服务实际返回的标识，后续比较不能把别名当已固定快照。DeepSeek枚举仅为契约预留，不等于第二适配器已经完成。

Runtime追加真实assistant回复时携带该字段；既有JSON快照自然保留，不改SQLite表或迁移。旧JSON仍可读，旧程序不保证读新字段。数据编码为：原user消息 → 完整原生reasoning/function_call → 对应function_call_output → 完整原生回答 → 新用户追问；不在API层再造工具循环。

回放前核对状态归属和可见投影，实际片段：

```python
if state.provider != "openai.responses" or state.model != model:
    raise ValueError("提供商或模型状态不匹配")
projected = parse_response({"status": "completed", "model": state.response_model, "output": state.output}, model=model)
```

随后按保留JSON类型的文本/调用投影比较，内容或参数不一致就拒绝；不会把跨模型密文交另一提供商，也不会静默使用一份与可见历史矛盾的旧缓存。没有原生状态的旧消息只重建可表达的普通文本/函数协议，不发明reasoning。

可类比C++值对象同时保留业务投影与用于协议往返的原始变体。入口/返回按既有Pydantic重新校验和深复制；不透明payload仍是数据，不能获得权限。相比只在适配器维护响应缓存，消息内保存稍重，但重启、两个session及换新模型对象不会错用缓存。代价是更多磁盘/序列化与完整历史大小；未来压缩/归档需保留协议边界，S31尚未实现。

本地数据库并未因此整体加密：只有提供商的reasoning字段是不透明密文，普通聊天/工具事实仍遵循此前本地明文存储的限制。
