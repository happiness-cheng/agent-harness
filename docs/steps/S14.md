## 接口与规则

- `Clock(time_zone="Asia/Shanghai", now=...)`：默认读取带UTC时区的系统时间；测试可注入回调。today转换到用户时区再取date，拒绝naive datetime或非datetime结果，不回退主机默认时区。
- `Clock.resolve_date(value)`：只接受date、规范YYYY-MM-DD、今天/明天/后天或None，返回date/None。含时刻的datetime也拒绝，不偷偷截断。相对词在写入时解析并固定；“下周五”等未支持表达需上层澄清，本步不是自然语言语义验收。
- TodoItem增加due_date:date|None，默认None；status仍仅pending/completed，deleted沿用已确认的逻辑删除策略。
- add支持可选due_date；update支持只改标题、只改日期或一起改。遗漏due_date表示保留，显式None表示清除；无字段仍TypeError。字段全部校验成功才一次替换，失败不部分写入。
- list_items继续返回事实记录副本；新增list_views返回冻结TodoView(item,overdue)，一次查询只读一次today。只有未完成且截止日期早于今天才逾期；当天不逾期、未来或无截止不逾期、完成项始终False，已删除项不展示。
- 日期更新/重命名/完成/删除保留其他字段及实际ID。逾期不自动完成或删除，也不创建提醒。返回快照不是实时推送，跨天后的展示由下一次查询重新派生。

## 实际核心代码

可信时钟先转换时区，再确定日历日期：

```python
def today(self) -> date:
    current = self._now()
    if not isinstance(current, datetime):
        raise TypeError("时钟必须返回datetime")
    if current.tzinfo is None or current.utcoffset() is None:
        raise ValueError("时钟必须返回带时区的datetime")
    return current.astimezone(self._zone).date()
```

相对日期按本地日历日加减，不把“明天”实现成UTC时刻加24小时：

```python
relative_days = {"今天": 0, "明天": 1, "后天": 2}
if value in relative_days:
    return self.today() + timedelta(days=relative_days[value])
```

resolve_date对绝对日期还检查`absolute.isoformat() == value`，避免date.fromisoformat接受紧凑格式或ISO周日期后扩大接口语义。非法文本ValueError，非法类型TypeError；不会猜测含糊表达。

update在检查归属、严格UUID、当前会话内存活记录之后构造补丁：

```python
if title is _UNSET and due_date is _UNSET:
    raise TypeError("update至少需要title或due_date")
changes = {}
if title is not _UNSET:
    changes["title"] = title
if due_date is not _UNSET:
    changes["due_date"] = self._clock.resolve_date(due_date)
# 保留不可改字段，完整校验成功后再替换；不使用跳过校验的副本更新。
updated = TodoItem.model_validate({**current.model_dump(), **changes})
items[item_id] = updated
return updated.model_copy(deep=True)
```

_UNSET是私有Enum单例标记，与合法None不同。全部查找/解析/校验/替换在同一RLock内；日期无效时不会先写标题，标题无效时也不会先写日期。无效归属拒绝在读取时钟之前；未知/外session/已删除ID也先拒绝，再解析相对日期，沿用统一KeyError。

逾期只在展示查询中派生：

```python
def list_views(self, context: ExecutionContext) -> list[TodoView]:
    items = self.list_items(context)
    today = self._clock.today()
    return [
        TodoView(
            item=item,
            overdue=item.status == "pending" and item.due_date is not None and item.due_date < today,
        )
        for item in items
    ]
```

list_items复用已有归属、过滤及深副本；展示只使用该次记录快照及单次today，不回写业务数据，不持有锁调用外部模型。Clock是可信配置，本步没有任意回调故障降级或自动纠正不准确的系统时钟。

## 一次具体的数据流

1. 注入固定时钟：UTC 2026-10-20 15:59:59，即上海10月20日23:59:59。新增“今天截止”保存date(2026,10,20)，查询overdue=False。
2. 推进时钟到UTC 16:00，即上海10月21日00:00；重新查询overdue=True，但存储记录仍pending、due_date仍10月20日，没有自动完成/删除。
3. 此时新增“明天截止”保存10月22日；之后推进到更晚日期也不会重新解释这个相对词。
4. 完成第一条，再推进到2027年，overdue仍False；更新另一条due_date=None可清除截止。标题与非法日期一起提交时整次更新拒绝，原字段都保留。
5. 错误owner查询展示被拒绝，会话历史及running任务不变；记录JSON只保存绝对日期，不含overdue派生字段。

以上直接运行真实内存服务，日期来自可控回调，不是假模型结果。另实际执行默认UTC时钟/IANA时区烟测，均退出0；没有真实等一天、LLM、凭据读取或业务数据外发。

## Python机制、C++类比与取舍

- `now: Callable[[], datetime]`类似C++注入`std::function`时钟，生产函数和测试回调走同一业务逻辑；不改全局时间或sleep。S08的perf_counter用于耗时，不能拿来判断日历日期。
- Python date只保存年月日，类似日历值对象；datetime表示时刻，两者不混用。aware datetime加IANA时区转换后才取日期，测试覆盖上海午夜、负/正时区及洛杉矶夏令时跨日。
- 私有遗漏标记相当于区分“没有提交补丁”与“明确提交空截止”；单独用None无法同时表达这两种操作。现在有标题/日期两个可改字段，保留窄关键字接口和最小补丁语义，没有通用任意字段更新框架。
- RLock作用域接近RAII锁；完整Pydantic验证后赋回接近先构造有效值对象再提交。Type注解本身不提供运行时校验，实际检查不可省略。
- 不选每天后台把status改成overdue：会引入调度、漏执行与冗余状态一致性问题；选择查询投影，代价是每次查询重新比较日期且调用方需刷新展示。完成事实和截止日期独立于当前时间，旧快照保持原值。
- 不把due_date改成某个午夜datetime：它会额外绑定时刻/时区，容易与提醒混淆；本步只存绝对日期。也不写死UTC+8冒充IANA时区，保留其他时区/DST规则。

当前仍是内存服务，无数据库持久化、提醒、自然语言意图授权或多用户时区配置。相对日期解析只支持列明的三个词；系统时间准确性和配置时区由可信入口负责。业务日期不代表已安排提醒。
