## 接口、核心代码及一次具体数据流

以下是已交付公共接口的用法，model与tools由可信应用提供：

```python
ledger = BudgetLedger(BudgetLimits(model_calls=10, tool_calls=4))
segment = ledger.start_segment(BudgetLimits(model_calls=2, tool_calls=1))
result = Runtime(
    model, tools, budget=segment,
    checkpoint_policy=CheckpointPolicy(reserve_model_calls=1, reserve_tool_calls=0),
).run("计算后继续核对完整目标")
checkpoint = result.checkpoint
```

真实路径：模型第1次提出calculator → 原账本调用前扣工具1 → 结果0.3追加历史 → 下一普通模型调用前发现只余模型1 → 用这1次做无工具收尾 → 校验四组文字 → 返回partial/budget_checkpoint及检查点。累计模型2/工具1，calculator只执行1次。

remaining的核心实现：

```python
with self._ledger._lock:
    owners, node = [self._ledger], self
    while node is not None:
        owners.append(node)
        node = node._parent
    return BudgetLimits(**{
        resource: min(getattr(owner._limits, resource) - owner._counts[resource]
                      for owner in owners)
        for resource in _RESOURCES
    })
```

@property只提供读取，不扣额或落盘。类似C++在持锁作用域计算值对象，但Python类型注解本身不校验，这里由Pydantic严格对象检查类型。锁退出后兄弟片段仍可能消费，remaining不是预订凭证；consume的原子硬检查始终保留。

Runtime普通模型调用前的实际分支：

```python
if self._checkpoint_policy is not None and (
    self._budget.remaining.model_calls <= self._checkpoint_policy.reserve_model_calls
):
    return self._close_checkpoint(messages, context, run_id, parent_call_id, "model_reserve")
```

工具则在批次每次派发前检查工具预留。触及时为当前及后续未启动请求配齐not_started，再收尾；已返回结果保留，不重新执行。这类似C++控制循环先选择收尾分支，再调用函数，不是函数执行后才检查超额。

收尾仍先self._budget.consume("model_calls")，共享累计、父级限制和S19-b消费前SQLite提交门；随后model.generate(model_messages)，不给tools。绑定业务工具时也加入系统提示及最新application_state，让模型看到已确认目标/约束/模式。只允许ModelResponse.stop且JSON通过CheckpointNote校验；不做格式修复请求或第二次整理。

## 检查点内容与可信边界

CheckpointNote四组字段achievements/pending/blockers/next_steps必填，每组最多20项、每项1—1000字符且非空白，额外字段拒绝。它们是未核实的模型文字。frozen与tuple避免通常赋值修改，但frozen不等于所有嵌套对象深层不可变；BudgetUsage里的字典是独立快照。

Runtime单独收集tool_results：message_index/call_id/ok/execution_state；ok=True表示工具成功返回，不等同于新增副作用或业务完成，比如重复完成todo可能changed=false。索引指向原始完整messages，不是添加system/application_state后的临时模型输入；history_length记录原始历史长度。独立run没有历史存储，调用方须另保留消息；run_session可查原有保存历史。索引尚无持久冻结版本或引用授权，S20-b再处理。

收尾stop也始终返回partial，不会凭模型“全部完成”转completed或授予权限。正常回答在阈值前仍可completed/checkpoint=None；无策略的旧Runtime保留用完最后一次正常回答的行为。本步不声称所有入口自动启用软阈值。

## 失败与取舍

- 硬额度0：不发收尾请求；partial/budget_exhausted、closing_status=not_started、model_note=None，已有引用和观测计数仍返回。
- 收尾预扣存储失败：failed/budget_persistence_failed，不调用模型；沿用旧句柄停用，不自动重试。检查点用量是观测内存快照，提交结果未知时需重新从SQLite加载，不能当作已核定余额。
- 模型异常：只记录固定model_call_failed，不回显异常正文，已扣次数不退还。
- 截断、拒绝、非法JSON、额外字段、非ModelResponse或请求工具：不执行工具、不伪造整理文字。closing_status=failed或invalid_response；外层partial/budget_checkpoint，closing_error记录具体固定分类。

采用显式剩余次数预留，默认模型1/工具0，避免固定90%在小预算下没有收尾空间；可设置其他非负工具预留、至少1次模型预留。reserve_model_calls大于1时也只调用一次收尾，剩余额度不自动消费。

未选“收尾继续开放工具”，因为可能继续写业务或延长循环，代价是收尾不能补办业务；未选新开无限预算写摘要，因为会绕过累计。模型失败时接受没有整理文字，保留事实引用。未新增SQL检查点表，先验收返回协议，下一子步复用现有快照处理恢复。

预留是同步边界策略，不是兄弟片段间的独占预占。共享调用可能先花掉额度，硬门仍拒绝，退化为无模型文字的检查点。增加收尾会增加调用成本和延迟；原输出token/HTTP请求数/超时限制仍独立生效，不估算精确费用。

本步只在预算边界生成检查点，不覆盖所有工具异常、进程中断或未知结果。当前同片段重复运行也没有S20-b的定向确认门；业务崩溃/响应丢失/幂等仍未解决，不保证exactly-once。
