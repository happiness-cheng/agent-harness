# M02：Memory完整评测材料

## 阅读说明

当前正式版本为v2。这里逐例列出全部合成历史、问题、判据和真实离线输出；没有运行回答模型，因此没有“模型回答”。不能把下方期望行为当成真实回答。

本轮没有修改生产Memory。固定输入32例，开发16、公开验收16；不是盲测。书中60例只做只读清单审计，未运行其模型或裁判。评分协议见[M02-memory-rubric.md](M02-memory-rubric.md)，机器可读完整输入见[固定集](../acceptance/m02-memory-suite-v2.json)，逐来源输出见[基线](../acceptance/m02-memory-baseline-v2.json)。

v1错误地把不应提供的无关/未经核实/已撤销偏好来源均计为硬泄漏；v2新增硬禁止来源区分。原问题、历史、预期事实及原来源集合逐例比较不变；保留v1报告。5→2仅为评测器纠错，绝非Memory优化。

## 真实基线总览

| 对照 | 必要来源取全（26例） | 无需记忆却多取材料（6例） | 硬边界违规 | 正文UTF-8字节合计 |
| --- | --- | --- | --- | --- |
| no_memory | 0/26 | 0/6 | 0/32 | 0 |
| legacy_current_session | 0/26 | 0/6 | 0/32 | 0 |
| full_history_diagnostic | 26/26 | 4/6 | 2/32 | 10900 |

当前会话召回全空是原设计不支持跨会话的结果。它没有发生可观测泄漏，不能证明具备目标中的跨会话隔离/遗忘。完整历史诊断保留基本用户/时间/会话边界，但会泄露两例明确禁止跨会话回忆的材料；不是安全的生产方案。

同会话召回、SQLite重开、同用户不同会话拒读、不同用户拒读4项控制均为真实执行且通过；这些仅证明现有原文引用边界。

## 核心实现：先取回，再独立对照标准

像检查图书管理员：先看他实际拿来了哪些书，再核对所需书单；不能因为图书馆里藏着那本书，就算他已经找到了。

代码入口[scripts/eval_memory.py](../../scripts/eval_memory.py)；以下为实际实现节选：

```python
def component_input(case):
    """gold不进入被测组件；不同用户分别入库，留给组件接受隔离挑战。"""
    query = {k: case['query'][k] for k in ('owner', 'session', 'at', 'text', 'retrieval_query')}
    histories = [deepcopy(h) for h in case['histories']
                 if instant(h['available_at']) <= instant(query['at'])]
    return {'histories': histories, 'query': query}
```

`component_input`只交历史与问题，不交gold。`legacy_retrieve`实际创建不同owner的SessionStore会话，通过begin/append/finish归档，再从新会话调用MemoryJournal.select；没有提前打开跨会话权限。`full_history_retrieve`只作为诊断。`score_retrieval`是评测器，不能用于给被测模型筛答案。
