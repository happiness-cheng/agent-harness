## 比较范围（先固定再实现/运行）

- 不改候选生成：统一原候选 cap=100，使用v0.3实验排序B作为R0。
- R1只做单一机制：在同一候选上，以“当前原句子句中显式匹配请求属性的绑定”稳定分层，其余保持R0次序，不改任何旧权重。未知不补齐，不把邻句号码归到当前实体。
- R0/R1各自Top-8内比较P0整条原文、P1完整句子的提取式证据、P2同样证据包的预算选择。预算均2048 UTF-8紧凑序列化字节，不是精确Token。
- P1/P2原句逐字摘录；保留源ID、源情景、来源实体范围、观察时间/有效区间、证据类型及字符范围；否定/条件/时间限定句强制保留；不截断词句。无法完整放入就不放，未知主体不推断。
- P1按Top-8顺序整包装入。P2在8包子集上穷举预算内方案，固定效用：倒数排名之和 + 0.5×匹配请求的不同显式绑定数 + 0.1×查询词覆盖率；相同完整证据在同一情景仅计一次效用，平分时取更小字节/原序。完整性约束优先。
- 绑定类型：预订/确认号、会员号、订单号、房号、账户号、routing、电话号、PIN、折扣码、座位号。只接受本子句的显式标签和值；来源provider只叫entity_scope，不冒充精确实体确认。子句问句不惩罚同消息的独立陈述。

## 数据、Gold与边界

- v0.3所有20题是已见开发集；保留原Gold与原始成绩。
- 新保留样本从剩余40题按层级/文件名各取第一题，共3题。样本很小，不声称泛化或独立专家盲评。
- 主指标沿用原规则；新Gold也带来源锚点。额外等价来源仅在独立审阅实体、属性、值、时间及限定一致后进入单独指标。保留拒绝/未知决定，不自动把同值当等价。
- 新3题与旧租车/酒店两题进行完整的小批证据审核；其他已见题不冒称已审等价来源。主体/属性可以由被审原句/已提供来源元数据证明，不能由模型输出倒推。
- 已审必要证据字段用于事后完整证据保留率；另报机械限定句保留率，二者不能混为语义完整性。
- 错误属性绑定率只在人工/代理源审的标注范围计算，同时报告预测审计覆盖率；未标注预测不是默认正确。排序选错来源与显式绑定错误分开。

## Oracle（全部仅评分后调用）

- 候选事实并集上界；同候选最多8条的精确Gold最大覆盖（事实mask DP）；实际Top-8覆盖。
- 实际Top-8内分别计算P0/P1的精确预算子集最优覆盖；另算候选池内最多8条预算最优覆盖。按mask/条数的最低字节DP，所有入选证据真实存在，不构造答案。
- 报告候选/排序/表示/预算选择各段损失；Oracle不进入检索、排序、装配。更换Gold不允许改变上述实际输出。
