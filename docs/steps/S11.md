## 实际核心代码

```python
def update(self, context: ExecutionContext, item_id: UUID, *, title: str) -> TodoItem:
    checked = self._sessions.check_access(context)
    if not isinstance(item_id, UUID):
        raise TypeError("item_id 必须是 UUID")
    with self._lock:
        items = self._items.get(checked.session_id, {})
        current = items.get(item_id)
        if current is None:
            raise KeyError("当前会话中未找到todo")
        # 保留不可改字段，完整校验成功后再替换；不使用跳过校验的副本更新。
        updated = TodoItem.model_validate({**current.model_dump(), "title": title})
        items[item_id] = updated
        return updated.model_copy(deep=True)
```

归属检查先于ID和标题检查。只搜索当前session的桶，不遍历其他会话；未知及其他会话ID统一KeyError，不回显标识，也不判断它是否在别处存在。类型错误是TypeError；无效owner/session是PermissionError；标题违反契约是Pydantic ValidationError。Python对缺少必填参数或不支持参数的TypeError发生在进入方法体之前，不承诺这种调用也先做归属检查。

查找、校验、替换放在同一个RLock内；非法标题在赋值前失败，原记录保持不变。同一字典键替换值保留列表插入顺序；没有重建ID、重置状态或改变其他记录。返回深副本，旧快照仍表示旧标题。冻结对象方便约束正常调用，不是进程内恶意Python代码的安全隔离。

## Python机制与C++类比

- `*`后面的title必须以关键字传入，让调用表达明确。`item_id: UUID`注解本身不校验运行时类型，因此显式isinstance；字符串UUID也不会在这个业务接口自动转换，未来入口负责解析。
- `{**current.model_dump(), "title": title}`是新字典：先复制当前字段，再覆盖标题。接近C++“复制当前值对象，修改允许字段，再验证、赋回”的思路；这里model_validate负责真实运行时校验，不能把Python注解当作C++静态类型系统。
- `with self._lock`接近RAII作用域锁，异常退出也释放锁；没有依赖Python对象析构时机。当前是进程内锁，不是数据库事务或跨进程锁。
- `model_copy(update=...)`允许未经验证的更新；测试刻意在返回副本上构造title=None，证明确实不会污染存储。内部更新使用model_validate，合法返回后才采用普通深副本。

## 方案取舍与限制

选择窄的标题更新接口，调用方只提交想改的字段；服务内部基于锁内读到的最新记录构造完整新值。内部重建对象是校验手段，外部协议仍然是局部更新。

合理替代一是接收完整TodoItem并整对象覆盖；调用简单，但调用方需要携带ID/归属/状态，旧快照也可能覆盖最新保护字段。替代二是通用可选补丁对象；适合多字段及遗漏/显式空值语义，但目前只有标题，会增加尚无用途的分支。因此本步不加通用补丁类；将来确有多字段再扩展。

代价是每次构造/校验新对象并复制返回值；对当前小记录可接受。锁内读改写防止操作交错，但没有版本号或乐观冲突检测，两次合法请求修改同一标题是后写生效。重复设置同一标题不新增/合并记录，没有时间戳、事件或额外副作用，不把它泛化成基础设施重试保证。

记录仍在服务实例内存中，重启或新建服务会丢失。真实登录、持久化、模型工具授权、完成/删除、日期/提醒均不属于本步；上下文由可信入口提供。S16才接模型业务权限。
