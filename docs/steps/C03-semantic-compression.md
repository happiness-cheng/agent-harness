## 评价基线与边界

实施前四个压缩测试文件：37 passed。旧实现即使模型选中多条相关原句，也会按规则分数逐句丢弃普通候选；仅修排序或增加 raise 没有实现预算不足后的压缩流程。

引用检查只能证明来源 ID、原文位置、哈希与覆盖成立；不能证明摘要语义忠实、没有遗漏句间关系或没有幻觉。语义摘要明确标为 unverified；真实模型质量需要另行有界授权评测。

一条完整原句本身超过模型输入窗口、必要引用元数据无法容纳、层数/调用/修正预算不足时，保留原文并暂停。目标是实现有界回退，不宣称任意输入都能无损压缩。

仅规则命中的独立相关性复核仍要求整份判断依据能进入一次受限请求；其超窗会在语义压缩之前暂停。本次分块覆盖语义改写阶段，没有实现跨块相关性复核。

## 核心控制流

```python
plan = prepare_complete_selection()
if fits(render_excerpts(plan)):
    return render_excerpts(plan)
items = compressor.compress(plan.excerpts, objective, max_bytes, render=render_summary)
return render_summary(items)
```

模型路径没有逐句贪心 continue；语义压缩先减少表达冗余，程序负责预算、引用和发布时机。输出不合格最多修正一次，全部检查通过后才切换可见版本。

`ExcerptOverflow` 是携带完整候选的内部状态：工具摘要与历史压缩会捕获它，再按最终序列化结果判断是否调用语义压缩，不是直接把异常交给用户。历史正文超过旧3500字节阈值而完整JSON仍在6000字节以内时，保留全部原句，不增加改写调用。

`render` 是程序提供的结果组装函数，包含正文、引用和元数据。压缩模块每次得到模型结果后调用它测量完整字节数，不能仅相信模型自己报告的长度。改写摘要使用 text，逐字摘录才使用 quote；两者分别关联真实证据索引。
