## 已确认事实与纠正

当前SkillCatalog.summaries采用self.read(name).splitlines()[0][:200]。这不是description解析器，会漏掉多行及200字符以后的内容。现有项目一份技能尚无frontmatter，不能假装有可提取的标准字段。

当前去重仅扫描最终可见的工具结果，旧正文不在时允许完整重读；尚未自动重注入。context.py仍把较长read_skill结果纳入普通工具摘要，整轮压缩也可移除原文。上轮13项测试验证了重读与去重边界，不证明Skill能跨压缩自动持续生效。

当前环境未安装PyYAML，pyproject.toml未声明YAML解析依赖。不能写yaml.safe_load后就声称代码可运行。

## 候选一：完整元数据读取

使用YAML frontmatter中的name/description。单行、折叠多行（>）、保留换行（|）都按YAML语义解析；完整读取解析后的description，不截第一行或任意前200字符。

借鉴Agent Skills的name与description契约，description非空、最多1024字符；超限或类型错误明确报错而不是悄悄截断。名称及重复键也要校验；缺失/损坏头部不能自动退回标题而伪装成功。

目录生成只读取至关闭的---标记，带头部读取上限；不构造整份正文。底层文本IO可能有缓冲预读，不承诺操作系统零字节触碰正文。使用成熟的安全YAML解析器，不自写正则假装支持完整YAML。新增依赖应明确声明、固定版本并验证安装；本轮不安装。

先完成现有平铺Markdown文件的元数据解析及样本迁移，暂不把目录结构、资源读取、动态脚本和权限扩展混入一个步骤；借用标准头部不等于已完整兼容Agent Skills目录规范。

示例：

```yaml
---
name: writing-polish
description: >
  润色中文文本，保持原意与事实。
  当用户要求修改措辞、整理表达时使用；不新增指标或成果。
---

# 执行方法
先识别事实，再调整表达。
```

目录中description应包含上面两行的全部含义。>把常规换行折叠成空格；|按YAML规则保留换行。所谓精确是保留字段语义，而不是把YAML标记及缩进原样塞给模型。

## 候选二：Skill在压缩中的生命周期

原则：当前仍需遵循的精简Skill规程不交给普通聊天摘要改写；详细参考资料继续按需读取。不是所有曾经加载的Skill永久驻留，也不是永久跳过预算。

建议维护已加载版本快照及内容哈希。压缩后，将仍适用且预算允许的规程重新放入模型上下文；同版本已有可见原文时不重复。恢复已加载快照，而不是悄悄读取磁盘最新版替换正在执行的规程；显式重新读取才接受新版本。

这意味着原始历史仍可归档，模型上下文单独保留或恢复规程。重注入必须保留来源/权限级别，不擅自升为system，也不把allowed-tools等元数据当成应用授权。

超出预算不能只截前几行后宣称已完整加载；应明确哪些未保留，缩小当前工作范围或按需重新加载。保留哪些Skill、如何结束适用期、总预算和重注入消息结构需在第二步设计具体化，当前没有假装已存在active-skills机制。

Claude Code公开文档描述：调用内容留在会话，相同内容重复调用用短通知；压缩后重新附加每个Skill最近一次调用，受每份和合计预算限制。本文借鉴“恢复规程+预算”的原则，不照搬其固定token数或将截断当前代码误称完整保留。

## 验证与推进顺序

先实施description解析，验证：单行、多行>、多行|、超过200字符仍完整；无效/缺失/超长字段明确报错；目录不构造正文；目录实际模型输入与字段一致。模型调用不是解析正确性的必要验证。

随后单独实施压缩生命周期，验证：普通工具摘要不改写当前规程；真实压缩后规则仍可见；未使用Skill仍不加载；同内容不重复；版本变化可识别；超预算明确处理且不破坏调用配对。
