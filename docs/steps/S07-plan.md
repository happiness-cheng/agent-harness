# S07：压缩边界的 Skill 适用性筛选

日期：2026-10-23。承接用户已确认的“压缩时判断适用性，保留整份原文”的设计。本轮无真实模型请求。

## 先固定评价标准

新增集成样本，测试输入由成功读取的合成 Skill、历史交互及离线筛选决定组成；不把人工决定冒充模型理解。通过真实 ManagedModel 输入边界判定：适用/不确定全文恰好一份；停用正文不再出现在快照或近期 Skill 工具结果；原历史不改；普通压缩请求不收到 Skill 全文；预算不足阻断；有效状态能跨管理器重建延续；新显式读取可以重新激活。没有窗口压力时不调用筛选。

开发样本验证保留/停用/不确定，固定验收验证停用延续、显式重读、非法分区保守退路、预算与无压力路径。标准与脚本先于生产实现固定，基线失败保留。离线模型提供固定输出，只验证接线和执行规则。

## 方案与取舍

沿用已确认方案：压缩准备阶段调用独立、无工具的选择器，整份 Skill 分成 keep/release/uncertain；程序校验 ID 完整分区，保留 keep + uncertain。正文不由选择器改写；哈希和调用 ID 来自原历史。调用共享父预算并留出至少一次主模型调用；窗口/预算不足或无效结果保守保留，Stop 则中断。

与“全部固定保留”相比可以移除无关正文，但多一次判断调用，判断质量尚需真实集成评测。与“把正文压缩成摘要”相比保留规程完整性；预算不足不能靠删规则过关。已有短样本 S05 分类结果不能证明本轮的真实任务判断质量。

首次触发后把全文放在独立快照消息里，把模型可见的原 Skill 结果替换成带名称/哈希/调用 ID 的短记录，保留工具配对；原历史不变。筛选状态只保存各来源 ID 的决定，不另复制正文。后续无窗口压力不重选；新显式读取的来源 ID 默认激活；下一次压缩可重评所有已加载最近版本。

普通 LLM 压缩的输入排除成功读取的 Skill 正文，但归档仍保存原始消息。主工作区的结构化层本来就只记录工具状态及来源，不改它。旧版本压缩摘要里可能已有的规程摘录不自动清洗，本轮不承诺迁移旧摘要。
