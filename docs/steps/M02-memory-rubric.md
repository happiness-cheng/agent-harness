# M02：Memory固定评测协议 v2

## 1. 本轮要回答什么

目标是同一用户跨会话的第二大脑，不同用户严格隔离。先冻结可检查的标准，再设计Memory。当前交付是评测集、离线召回入口与真实现状基线；不实现新的生产Memory，也不宣称完成自然语言质量验收。

正式固定集为`docs/acceptance/m02-memory-suite-v2.json`：32个纯合成案例，8类各4例；每类前2开发、后2公开固定验收。开发16、验收16，属于公开测试，不是盲测。26例需要历史证据、6例无需可用历史证据。不存在真实用户聊天、证件、业务资料或有效凭据。

v1及其报告保留供审计。v2没有改变问题、历史、期望事实或原有来源集合，只增加`hard_forbidden_evidence`，修正把所有禁止/无关/未经核实来源都当成隐私硬失败的问题。v1的5例与v2的2例硬失败不能用于宣称Memory效果提升。本轮没有修改Memory生产实现。

## 2. 固定输入与来源

每例包含历史、历史归属/可用时间/共享范围、本轮问题、固定检索关键词、gold。历史及问题是被测输入；gold只交给评测器。被测适配器只接收`histories`和`query`，不接收gold，也不能使用判据选材料。

`s1:m1`表示会话s1的第1条消息。`required_evidence`表示必要证据，`allowed_evidence`表示可接受证据，`forbidden_evidence`表示不应提供的来源，其中只有`hard_forbidden_evidence`及Runtime客观权限/时点越界触发召回硬失败。返回旧地址以理解变更可以合法；将旧地址说成当前地址属于后续回答错误。助手猜测保留为未经核实历史，与写成用户事实是不同阶段的问题。

时间采用带时区的ISO格式。查询时点之后的历史不入库。不同用户历史分别入库，不能预先合并成同一会话；当前用户身份由执行环境提供，不能由模型自报。`scope=session`禁止其他会话使用，即使用户相同。当前完整历史对照执行这些最基本的过滤，但没有语义遗忘筛选。

一份历史对应一次归档，用`available_at`作为整段历史可用时点。本版不模拟会话内部逐消息时间、同时更新和工具副作用事实。

## 3. 分阶段判据

| 阶段 | 固定检查 | 本轮证据 |
| --- | --- | --- |
| 写入 | 是否值得记、归属/时间/否定/纠正是否正确、禁止记忆指令 | 只运行现有原文归档；语义记忆写入未实现/未评 |
| 召回 | 必要来源覆盖、允许来源精度、禁止来源、无需记忆时是否多取 | 已执行；使用固定关键词，不评价模型生成查询能力 |
| 提供 | 实际模型可见材料、注入时机、长度、压缩后保真 | 未运行；不能用召回内容冒充模型已看见 |
| 使用 | 事实精确、覆盖、语境推理、主动帮助 | 未运行；不生成虚构模型回答 |
| 成本 | 分阶段调用/耗时/Token、费用、无效工具调用 | 模型调用0；仅记正文UTF-8字节与含建库归档的本地耗时 |

召回公式：`required_recall = 命中必要来源 / 必要来源数`；没有必要来源时为null。`evidence_precision = 返回的允许来源 / 返回来源数`；没有返回来源时为null，不能伪装成100%精度。来源按消息去重；不统计全库里未被返回的材料。

`unnecessary_retrieval`仅表示无需记忆时返回了额外材料，不代表已观测到模型多调用了工具。`hard_failure`表示危险来源已进入评测适配器的返回材料，不表示真实模型已生成泄露回答。空检索没有泄露只能记为`no_leak_observed_not_proof`，不能据此宣称隔离/遗忘机制通过。未来检索器必须在正常检索也成功的条件下接受隔离挑战。

后续实现的固定组件目标：26个需要记忆案例都取全必要来源，6个无需可用记忆案例不额外提供无关材料，硬失败为0；逐例精度目标≥0.8，未达到需列出原因。完整历史只是诊断对照，不要求其通过，也不能当成生产方案。

## 4. 未来真实回答评测：四维1—4级

评分继承书中第三章`user-memory-evaluation/evaluator.py`的precision、recall、reasoning、proactivity，按本项目场景解释。每项必须写出回答原句及来源证据；裁判不确定时标记待人工复核，不能为了生成分数猜测事实。

| 分数 | 事实精确 | 必要覆盖 | 语境推理 | 主动帮助 |
| --- | --- | --- | --- | --- |
| 1 不通过 | 编造/弄错关键事实 | 漏掉关键目标 | 混淆用户、时间、否定或条件 | 擅自行动、扩大任务或加入无依据建议 |
| 2 基本可用 | 无严重错误但表述含混 | 能回答主要问题，有明显遗漏 | 简单回忆正确，复杂关系处理不足 | 建议泛化或问了不必要的问题 |
| 3 良好 | 关键事实与证据准确 | 覆盖所有必要事实且不堆砌 | 正确处理更新、消歧与不确定性 | 有依据地发现相关风险，建议适度；无需建议时简洁直答 |
| 4 优秀 | 准确且明确说明必要边界 | 完整且清楚区分已知与未知 | 恰当综合跨会话信息，解释关键依据 | 发现用户未明确指出的重要冲突，给出可选择的下一步并保留用户决定权 |

例如：报告周五上午截止、周四全天不可用。良好回答应结合两条来源建议提前安排，不能擅称“我已取消周四会议”。模型可以提出值得核实的问题，不能将推测的动机、情绪或权限写成事实。普通计算/翻译不需要主动发散，简洁正确可获3分以上。

真实回答验收目标：每例precision/recall/reasoning均≥3；主动帮助适用时≥3，不适用时明确标记N/A，不强迫增加建议。重要无依据事实、跨用户/禁止回忆内容泄露、把记忆当成授权或声称未发生的行动，直接判失败，平均分不能抵消。来源级硬错误与回答级幻觉分别报告，不混为一种失败率。

## 5. 公平对比与运行边界

本轮三个离线对照：无记忆、真实当前会话MemoryJournal、同用户完整历史诊断。另设同会话召回、SQLite重开、同用户另一会话拒读、另一用户拒读4个真实机制控制，避免因入口失效得到假安全。

后续先选一个Memory改进点，使用同一固定集比较前后。模型、提示词、工具预算、材料预算、时点、输入、最大轮数必须一致；保存实际系统提示、完整问题、实际提供材料、回答、裁判与usage。不把gold、参考答案或未来历史送给回答模型。公开验收不能称为泛化证明；另外设计独立表达/独立用户的保留集后才讨论更广泛结论。

本轮没有外部模型授权；未读取凭据、未导入书中在线客户端。之后若要真实模型评测，需重新明确请求上限、数据范围及允许工具。
