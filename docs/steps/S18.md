## 核心代码与数据流

整体数据流：固定输入+合成授权状态→真实Runtime.run_session自动提供系统/工作状态→模型自行决定回复/工具→真实todo_registry/TaskController检查→真实TodoService执行或拒绝→工具结果回传→核验实际记录/调用轨迹→人工审阅可见回答。

实际每轮上限的关键代码（intent_cases.py的_TurnModel）：

```python
def generate(self, messages, *, tools=None):
    if self.calls >= self.limit:
        self.errors.append({"error": "intent_turn_budget_exhausted", "diagnostics": {}})
        raise LLMError("intent_turn_budget_exhausted")
    self.calls += 1
    try:
        return self.model.generate(messages, tools=tools)
    except LLMError as error:
        self.errors.append({"error": error.code, "diagnostics": error.diagnostics})
        raise
```

这是测试入口的装饰包装：Python通过generate接口把请求委托给同一个底层模型，类似C++包装接口再转发；它没有继承或替换Runtime的循环，也不把Python注解当权限校验。每轮计数是生成尝试次数，底层适配器request_count才记录实际HTTP尝试；整组始终共享同一个max_requests=16适配器，不能用新建场景重置总预算。

每轮最多2次：通常一轮选工具、一次接工具结果后回答。7类8轮最多16次，单次输出上限4096，固定deepseek-flash/high、同官方/responses/指定文件DeepSeek key和已批准本机代理，无自动HTTP重试；需要更多轮不自动放大。多轮查询或参数纠错可能碰到这个小验收上限，这表示当前用例未通过，不能伪称模型没有能力。

结果里structural_ok只表示状态/协议/授权符合用例；semantic_review始终pending，人工依据review_instruction逐条检查answer。provider_state/reasoning不会进入报告，原始异常也不会打印；只保留固定错误分类、安全diagnostics、调用名称、合成记录和可见回答。真实模型可能选择不同措辞，因此没有用关键词命中代替语义评价，也没有让ScriptedModel预选工具来冒充真实理解。

选用小型场景材料和现有pytest，而非新评测框架，减少依赖和学习成本；人工审阅比完全自动评分慢，但能识别“没有写却声称写了”“主动提醒承诺”等文字问题。尚未遇到真实失败时，保留提示词比堆新规则更便于归因。将来若需要大规模统计，可另行设计评分，但本步不扩展。
