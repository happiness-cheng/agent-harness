## 接口与资源约束

- CalculatorArguments：expression 必须是非空白字符串，原始输入不超过512字符，额外字段拒绝；供模型 Schema 及直接调用复用。
- calculate(expression: str) -> str：执行确定性的本地四则计算，语法/除零/资源越界时报 ValueError；Pydantic 参数错误具体类型为 ValidationError，它也是 ValueError 的子类。
- CALCULATOR_TOOL：名称、描述、参数类、handler 的可注册配置；不会自动修改全局注册表。
- 求值前最多128个 AST 节点；非零值的十进制数量级指数为 -100..100，作用于字面量和中间结果。超范围即失败，不返回 Infinity 或静默变成零。
- 仅 ASCII 数字与普通十进制字面量；不支持科学计数法、进制前缀、下划线、变量、函数、注释或其他 Python 运算。具体语法沿用 Python 表达式解析规则，例如部分前导零整数会被拒绝。

## 核心代码与数据流

先做字符串/长度校验，再限制字符和解析：

```python
source = CalculatorArguments(expression=expression).expression.strip()
if re.fullmatch(r"[0-9.()+*/\s-]+", source) is None:
    raise ValueError("表达式包含不支持的字符或数字格式")
try:
    tree = ast.parse(source, mode="eval")
except (SyntaxError, RecursionError):
    raise ValueError("表达式语法无效或嵌套过深") from None
if sum(1 for _ in ast.walk(tree)) > MAX_AST_NODES:
    raise ValueError(f"表达式最多允许 {MAX_AST_NODES} 个语法树节点")
```

这里的 mode="eval" 仅是 ast 的“解析单个表达式”模式，不会执行输入。字符限制挡住当前范围以外的记法；求值仍由下面的节点及运算白名单决定。512字符在解析前检查，节点预算在任何算术求值前检查。

允许的运算映射到显式 Decimal Context 方法：

```python
_BINARY_OPERATIONS = {
    ast.Add: Context.add,
    ast.Sub: Context.subtract,
    ast.Mult: Context.multiply,
    ast.Div: Context.divide,
}
_UNARY_OPERATIONS = {ast.UAdd: Context.plus, ast.USub: Context.minus}
```

递归求值核心：

```python
def _evaluate(node: ast.AST, source: str, context: Context) -> Decimal:
    if isinstance(node, ast.Constant) and type(node.value) in (int, float):
        literal = ast.get_source_segment(source, node)
        if literal is None:
            raise ValueError("无法读取数字字面量")
        return context.create_decimal(literal)

    if isinstance(node, ast.BinOp) and type(node.op) in _BINARY_OPERATIONS:
        left = _evaluate(node.left, source, context)
        right = _evaluate(node.right, source, context)
        if isinstance(node.op, ast.Div) and right.is_zero():
            raise ValueError("除数不能为零")
        return _BINARY_OPERATIONS[type(node.op)](context, left, right)

    if isinstance(node, ast.UnaryOp) and type(node.op) in _UNARY_OPERATIONS:
        value = _evaluate(node.operand, source, context)
        return _UNARY_OPERATIONS[type(node.op)](context, value)

    raise ValueError("仅支持四则运算、括号和一元正负号")
```

ast.parse 会生成数字节点，其中的小数 value 已是 Python float。实现只用它辨认节点类型，从源片段读取原始小数字符串，再交给 create_decimal，避免先经过二进制 float 后再转十进制丢失位数。type 检查也不把 bool 当作 int。

例如 `(1+2)*3`：解析成乘法节点 → 递归处理左侧加法 → 从原文读取1和2 → Context.add 得到3 → 读取右侧3 → Context.multiply 得到9 → 返回字符串"9"。括号和优先级由语法树表示，不靠字符串替换。

每次调用建立自己的 Context：

```python
context = Context(
    prec=28,
    rounding=ROUND_HALF_EVEN,
    Emin=-100,
    Emax=100,
    traps=[DivisionByZero, InvalidOperation, Overflow, Underflow, Subnormal],
)
```

所有计算都显式使用这个对象，不依赖或修改当前全局 Decimal 精度。测试把外部精度改为3、舍入改为 ROUND_UP，结果仍按本工具规则计算，且外部状态不变。捕获 DecimalException 后转为范围/无效运算错误；除数为零单独报告，包括0/0。

结果为零时直接返回"0"；否则 format(result, "f") 产生普通十进制文本，仅在存在小数点时去掉末尾零，避免把整数1000错误变成1。

## 方案取舍与 C++ 类比

选择 Decimal 是用户明确决定的精度方案。float 原生且简便，但其二进制表示会让0.1+0.2出现尾差。Decimal 的代价是计算和文本处理更重，并且有限精度下仍有舍入；例如1/3无法精确表示，不承诺所有有理运算都精确。

选择 AST 白名单解释四则语法，复用 Python 的解析和优先级处理。替代方案是自己写词法/递归下降解析器，可以完全定制数字语法，但代码和边界更复杂；通用表达式引擎会带来当前不需要的能力和依赖。这里只解释明确允许的节点，没有编译或动态执行输入。

C++ 类比：类似对表达式树写 visitor，依据节点种类递归求子结果，再查函数表执行相应运算。Python AST 对象由标准库生成；Context 方法承担十进制舍入，不等于 C++ 内建 double 的运算。Python 的前导符号等语法也不能直接视为 C++ 语法。

资源限制牺牲了超长表达式和极端大小数值，换来可预测的解析、遍历和输出规模。AST 库本身不被当作安全执行器或通用沙箱，输入范围及允许节点均由工具明确约束。
