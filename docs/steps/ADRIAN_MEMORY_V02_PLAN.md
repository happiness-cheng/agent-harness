# Adrian Memory v0.2 执行边界与冻结计划

基线：`b90f104c52cb321d7585accd1e8aa1a6758fe87a`，分支 `feat/adrian-memory-v02-local`。不修改 v0.1 报告，不改 Gold、重要性权重或 Runtime 架构，不调用外部模型，不导入私人记录。

## 先固定评价标准

- 开发诊断集：书中原有 8 道机器标注题，逐事实记录所有检索阶段；不声称泛化。
- 独立测试集：从其余 52 题按层级、文件名字典序各取前 2 题，共 6 题。先读原始证据制作带位置的 Gold，再运行检索。标注者是本轮执行者，非独立人工专家；不得根据输出修改 Gold。
- A 原始 Episode + 原 FTS；B 受控上下文化卡片 + 同一 FTS；C 同一卡片 + 精确实体/显式别名检索。固定 Top-K=8、max_candidates=100、top_g=3、context budget=2048 UTF-8 序列化字节；相同 owner、历史和最后会话时间截断。
- 指标：宏平均 Hit@8、Fact Recall@8、首个相关项 MRR、完整候选池事实覆盖、去重数量、预算可见事实覆盖、错误情景和具体例外诊断、存储字节/条数、局部检索耗时。真实模型/Judge/Provider Token 均 NOT_RUN。
- 语义边界：只做可解释的邻接上下文化，不调用 LLM 提炼；保留原句、角色、原始 Episode 与全部证据引用；不把 assistant 话语升级成用户确定事实。实体/别名只来自批准 Fixture 原文或显式受控配置；不读题目答案。
- 正确性门槛：离线完整池模式不得改变普通检索 Top-K；确认、owner、时效、场景、撤回仍先由现有权威过滤。去重按 ID，不按相似文本合并。

## 最小文件范围

1. `retrieval.py`：可选离线诊断，保留默认路径与分数。
2. `cards.py`：独立 MemoryCard 及批准 Fixture 卡片投影；保留原 Episode，不自动生产导入。
3. `retrieval_experiment.py` 与 `scripts/eval_memory_retrieval_v02.py`：固定 A/B/C、证据对齐、阶段归因与报告。
4. 对应单元/集成测试和固定测试集；三份交付报告与基线 manifest。
5. 已有长原文读取失败单独复现、定位、修复并独立提交，不计为 Memory 改善。
