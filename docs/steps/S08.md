本步记录运行、模型调用和工具调用的关联、耗时及结果，帮助定位“哪次运行的哪项调用失败”。只保存在内存，不写日志文件或外发；不实现session存储、任务状态或通用预算。

## 接口与固定字段

- TraceContext：可信调用方提供session_id/task_id，类型为UUID或None；严格校验、禁止额外字段并冻结。它们只是诊断标签，不是资源访问授权。目前尚未接入真正的session/task服务。
- TraceRecorder(clock=perf_counter)：span上下文管理器收集事件；events返回tuple快照，to_json只返回JSON字符串，不执行保存动作。
- TraceEvent：sequence、run_id、call_id、parent_call_id、session_id/task_id、operation、status、duration_ms、error_code、execution_state、source_call_ref/tool_ref。Pydantic严格校验，固定枚举，不允许任意payload；拒绝负数/NaN/Infinity耗时。
- Runtime默认持有自己的trace收集器，可通过构造参数trace显式注入；run增加trace_context，RunResult增加run_id，可关联查询本次事件。

每次run和每次子操作均生成UUID。模型事件的parent是run操作；工具事件的parent是提出该请求的model操作。这里的parent表示控制/因果关联：工具在模型返回后才执行，不表示工具耗时被包含在该model调用耗时中。run耗时包含整个循环及其中的诊断开销。

operation的completed只表示该操作正常结束。模型返回有效tool_calls时，该model操作可以completed，但整个run仍未结束。

## 实际核心代码

Runtime将公开run包装原有循环，让所有正常返回统一记录运行终态：

```python
run_id = uuid4()
with self.trace.span("run", run_id=run_id, context=context) as run_span:
    result = self._run(text, context, run_id, run_span.call_id)
    run_span.finish(result.status, result.error_code)
    return replace(result, run_id=run_id)
```

输入及context在创建事件前校验；context先导出再重新解析，即便调用方绕过构造校验也不能把任意字符串当session ID写入trace。私有_run保留S07的循环决策，分别给模型调用（含响应校验）和工具调用添加span。

收集器的异常与收尾处理是：

```python
try:
    yield span
except BaseException as error:
    interrupted = not isinstance(error, Exception)
    span.finish(
        "cancelled" if interrupted else "failed",
        "interrupted" if interrupted else "unexpected_error",
        "unknown" if operation == "tool" else None,
    )
    raise
finally:
    self._events.append(TraceEvent(
        sequence=len(self._events) + 1, run_id=run_id, call_id=span.call_id,
        parent_call_id=parent_call_id, session_id=context.session_id, task_id=context.task_id,
        operation=operation, status=span.status,
        duration_ms=(self._clock() - started) * 1000,
        error_code=span.error_code, execution_state=span.execution_state,
        source_call_ref=sha256(source_call_id.encode("utf-8")).hexdigest() if source_call_id is not None else None,
        tool_ref=sha256(tool_name.encode("utf-8")).hexdigest() if tool_name is not None else None,
    ))
```

span开始时用单调时钟保存started。离开with时生成一条已结束事件，事件sequence按完成顺序递增。异常原文和堆栈都没有放入事件；异常记录后仍向上抛。Runtime已有的普通模型/工具错误在其处理分支中设置固定码；KeyboardInterrupt/SystemExit等未被吞掉，相关子操作和run均记cancelled/interrupted。

TraceSpan是作用域内的可变收尾对象，未显式finish时默认failed。持久在收集器内的TraceEvent则冻结，字段均为标量或UUID；events元组不能修改内部列表。Pydantic构造校验与冻结是普通API边界，不承诺阻止可信Python代码刻意使用绕过校验的方法。

工具事件的状态对应执行阶段：

| 工具路径 | status / error_code | execution_state |
| --- | --- | --- |
| 正常文本结果 | completed / None | returned |
| 未知工具 | failed / unknown_tool | not_started |
| 参数校验失败 | failed / invalid_arguments | not_started |
| handler普通异常 | failed / tool_execution_failed | unknown |
| handler返回非文本 | failed / invalid_tool_result | returned |
| handler中断 | cancelled / interrupted | unknown |

returned仅表示handler返回，不证明持久副作用或业务目标；unknown保守表示无法据此认定未执行。请求错误经模型修正后，早期failed工具事件不会被改写，最终run仍可completed。重复ID在执行前拒绝，不生成虚假的第二次tool事件；截断/拒绝/错误响应夹带请求时也不生成tool执行事件。

## 敏感内容边界

事件没有消息正文、提示词、参数、结果正文、公开推理摘要、Schema、异常正文或任意metadata字典的入口。不依赖“识别出某种密钥格式才遮盖”，而是避免将这些字段送入事件。

原始工具ID和名称可能来自模型，因此只存SHA-256引用。关联时用run_id加source_call_ref定位请求，tool_ref用于定位相同名称；可由已知原值重新计算哈希。它们是可关联化名，不是加密，也不保证低熵名称不可猜测；敏感正文则完全不收集。

session/task仅接受UUID，防止不小心把自由文本或凭据当诊断标签传入。Runtime不把这些trace标签、事件或错误堆栈追加到模型消息中。日志只是诊断观察，不能成为新增todo、已写入业务记录或任务已完成的权威依据。

## 具体数据流与时钟测试

脚本模型先请求真实calculator计算0.1+0.2，再回答：

1. run创建UUID、保存调用方构造的session/task诊断UUID，开始run span。
2. 第一条model事件记录有效工具决策completed。
3. tool事件引用第一条model的call_id，实际calculator返回0.3，记录completed/returned。
4. 第二条model事件收到真实工具结果，再返回stop；run最终completed。
5. 完成顺序为model、tool、model、run；RunResult.run_id与四条事件一致。

单元测试用每次递增0.125秒的TickClock替代真实时钟，无sleep。直接回答的model精确125ms、run375ms；工具链中各子调用125ms、run875ms。它们是注入时钟的确定性验收值，不是系统性能基准。手动演示使用默认真实perf_counter，只断言耗时非负。

## Python机制、C++类比与方案取舍

`@contextmanager`把yield前后的逻辑变成with的进入/退出；finally在正常return和Python异常展开时执行。职责类似C++作用域守卫或RAII，但这里依靠显式with退出，不依赖Python对象析构时机；进程被强杀时也不能保证记录完整。

`dataclasses.replace`基于已有结果构造带run_id的新结果，保留frozen结果对象的赋值约束；类型注解本身不验证字段，事件的运行时校验来自Pydantic。

| 当前选择 | 合理替代方案 | 取舍 |
| --- | --- | --- |
| 固定结构元数据 | 自由文本日志或全文记录后清洗 | 可按ID/状态查询，降低正文泄漏面；排查时看不到原始内容 |
| 离开作用域时一个事件 | start/end双事件或实时流 | 事件量少、配对简单；正在卡住的调用暂时没有完成事件 |
| 注入单调时钟 | 真实sleep / 用墙上时间相减 | 测试确定、无等待；仅记录耗时与完成顺序，没有绝对时间轴 |
| 默认内存收集器 | 磁盘日志/远端观测SDK | 无新依赖、无外发与文件生命周期；重启丢失，当前没有留存上限 |
| 本地轻量span | OpenTelemetry等完整观测体系 | 容易阅读与验证；不承诺外部trace协议兼容、采样、跨进程传播或并发安全 |

收集器和注入clock属于可信基础设施，要求时钟正常单调且可调用；没有远端sink故障降级或任意插件隔离。当前同步代码未验证多线程共享收集器。成功循环仍无通用轮次预算或主动超时，trace会随调用累积；这些限制没有因本步测试通过而消失。
