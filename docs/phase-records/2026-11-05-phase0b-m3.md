## 实际实现

- [activity_records.py](../../src/min_agent/activity_records.py)：Codex rollout、DSH v4、DSH old Profile；记录 ID 只包含冻结 Locator 字段，不包含 Fingerprint。独立 struct/payload/record 三层哈希。required 缺失时 native_record_id/canonical_event_id 为 null，provisional ID 由来源范围、observation_run_id、顺序占位派生。
- [activity_m3.py](../../src/min_agent/activity_m3.py)：在 M2 同一个 SQLite 事务中追加传输事件与来源记录；事件提交后才推进 Checkpoint。批次预检冲突后放弃整个批次，仅在持有同一写锁的事务中追加冲突证据，提交后报 record_conflict。重新打开或旧连接写入仍拒绝；没有回滚后另开事务的冻结空隙。
- 同 Locator 同 Fingerprint 不重复来源记录；不同 Locator 同 Fingerprint 保留两条，动态标 is_same_payload。内容变化不能派生新身份绕过冲突。
- Provisional 映射只搜索同 member/stream/generation 的候选。唯一候选还需要明确证据类型、source_id、target_id、reference；追加 IdentityTransition，不改历史。多候选返回 frozenset，保持 unresolved，不排序选胜者。
- [activity_store.py](../../src/min_agent/activity_store.py) 增加默认 stream namespace 参数；[activity_m2.py](../../src/min_agent/activity_m2.py) 提供应用标记/版本/校验入口复用，原默认行为不变。M3 独立应用标记阻止旧 Store 绕过校验。

## 限制与审核入口

仅合成 JSONL envelope，structure/payload 是显式内容分区；Locator metadata、时间与观察信息不进入内容指纹。Codex jsonl/zst 均使用已经解压的坐标；不实现真实文件解析或解压。DSH old 的 seq/seq0 各自一个实验库、stream 与 checkpoint，无跨库原子事务承诺；old 可选 offset 未知为 null，后续补充 offset 不重写旧身份。

一个冲突会保守冻结该 stream 库所有写入；仅允许只读检查，无自动解冻。外部证据真实性不由本模块证明；即使提供目标，多候选仍不自动消歧。创建/重建均新路径，不迁移 M1/M2 旧库或生产库。无真实私人历史、Hook、插件、模型、Memory 接入，无 M4–M6、性能/断电验证。

独立审核第一步：核对源码指纹，重跑上述固定测试，重点检查记录 ID 输入、冲突事务边界、持久冻结和映射证据。M1–M3 通过仍须独立审核及用户对独立副本写路径授权，不自动启用 Connector。
