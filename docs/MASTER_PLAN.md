# Adrian：完整目标架构与全程研发计划

更新：2026-10-30。用途：回答整个Adrian要做什么、为什么、已经做到哪里、接下来按什么顺序交付。制定计划不代表批准执行所有阶段。

**现在发生了什么？** 先前说明把V1.4的B2/C/D纠错闭环当成了总计划，范围答窄。最初交接还明确要求Context、Memory、Skills、长任务、多Agent、个性化与系统级持续改进。

**我们的目标是什么？** 做一个能理解目标、使用记忆与工具、安全持续执行、判断真实结果、有限纠错并从证据中改进的个人Agent。像可靠助手一样，既会做事，也能交代依据和边界。

**我建议怎么做？** 保留已有Runtime和已收尾能力，按下面的完整能力版图分批补齐。A维护设计/证据/验收，外部B整批实现；各领域先核心可用，不一次追求完美。

**做完后应该得到什么结果？** 逐步获得可核验的任务闭环、日常工作台、长任务与受控协作，以及候选隔离的改进流程。每阶段均有可见输出和明确停止条件。

**现在需要你做什么？** 目前不需要你操作；本轮只补全总设计与计划，不启动后续编码或付费实验。

## 2. 完整架构：围绕一次任务的闭环

```text
可信用户入口：请求 / 确认 / 取消 / 纠正
                    ↓
目标、约束与验收条件 → 可调整计划
                    ↓
上下文组装：当前任务状态 + 相关Memory + 按需Skill + 已交付证据
                    ↓
模型决策 → Runtime检查身份、许可、预算、执行范围 → 工具或受控子任务
                    ↓
真实业务状态、操作收据、原文Artifact与执行Trace
                    ↓
可信观察 → 独立验证 → 失败事实与待证假说 → 有限公开反馈
                    ↓
纠错提案 → 安全门 → 获准的有限补做 → 重新观察与验证
                    ↓
向用户交付结果 / 部分成果 / 等待确认 / 明确停止

横向约束：用户隔离、数据权限、资源预算、审计、版本、评测与发布
长期旁路：经用户确认保存Memory；从失败证据提出隔离改进候选
```

这是职责划分，不是要求新建一批服务。主入口仍使用现有Application、Runtime、Session和SQLite；新职责优先小函数/适配器。评测隐藏标准与内部审核事实不能直接进入模型反馈，也不能偷换用户公开目标。

### 对象和接口应怎样分工

| 对象 | 谁提供、解决什么问题 | 不能混淆什么 |
|---|---|---|
| 用户身份与ExecutionContext | 可信入口提供owner/session | 模型参数、历史文本不能自报身份 |
| Goal、Plan、Task、Attempt | Goal定义结果与约束；Plan可调整；Task组织逻辑工作；Attempt记录一次执行 | 改计划不等于获准改目标；续跑不重置权限预算 |
| 授权与预算 | 用户/可信host确认，Runtime在执行边界核对 | 进度、风险标签、Memory和模型建议都不是许可 |
| Session与Context | Session保存持久历史/状态；Context是本次模型请求的工作视图 | 压缩不改权威事实；模型没看到的材料不能宣称已使用 |
| Artifact、Trace、Receipt | 分别保留原始材料、执行过程、真实操作结果关联 | 日志写了工具名不等于动作成功；原文存在不等于本轮读过 |
| Observation与Verification | 前者描述有来源、版本、scope的事实；后者按冻结规则判断 | 未知不当失败或成功；机械校验不等于语义正确 |
| FailureReport与PublicFeedback | 内部记录事实和假说；公开层只暴露可披露、与当前目标相关的反馈 | 猜测不是根因；隐藏验收答案不交给模型 |
| RecoveryProposal与执行 | 提案表达建议动作；安全门单独准入；执行后重新验证 | 建议本身无执行权；未知写入不能直接重试 |
| 长期Memory | 有来源、范围、确认、时效和删除规则的历史知识 | 历史偏好不覆盖当前明确指令，历史说法不变成实时事实 |

## 4. 全程执行顺序：建议按整批交付

以下P编号是本总计划的工作包，**不是新版本发布号或已获准派工**。B2/C/D仍沿用原编号。

| 工作包 | 前置与具体范围 | 可观察交付及收尾标准 | 暂不做 |
|---|---|---|---|
| P0：收尾当前B2 | 原固定候选；外部B集中修权威观察与调用前许可两个入口，A复验，用户决定合入 | 失效证据WITHHELD；检查前撤权后端调用0；正常读取/重启/默认off保持，阶段记录完整 | 重开B0/B1、语义评分、工具分类 |
| P1：接通可信事实到反馈的必要链路 | B2核心通过；盘点已有Verifier/FailureReport/公开反馈与部分证据接口，只接入选定Todo和研究读取场景真正需要的部分 | 能指出真实未完成项、来源和限制；有读取却未送达时明确区分；隐藏标准不进入反馈 | 整包移植旧V1.2/V1.3、多目标通用化、任意研究结论自动判真 |
| P2：C/D安全决策与有限纠错 | P1的选定场景事实可核对；先C只读模拟，再按批准范围进入D | 一个合成Todo任务可从未完成到有限补做再验证；取消/撤权/UNKNOWN/预算均正确停止；合法查询不被UNKNOWN本身挡住 | 未授权真实外网、任意远端写入、自改代码/Memory |
| P3：日常可用与面试可讲的版本 | 最小纠错闭环通过；复用现有工作台，以一个日常任务贯通状态、证据、成本和用户决策 | 可重复本地演示；用户看懂完成/部分/未知/等待；关键代码导读、开关、已知限制与运行材料同步 | 界面大重做、功能堆叠、把离线演示说成真实模型改善 |
| P4：长程可靠性与Context/Memory质量 | P3可用后，根据真实失败优先级成批改善；长任务前完成其必要费用/时间/Token门和诊断 | 一个限定长任务暂停/重启保留成果；一次有代表性的上下文或Memory问题有同条件前后对照；无收益如实保留 | 同时换检索/压缩/模型以至无法归因；无限扩大记忆或实验 |
| P5：异步任务与受控协作 | P4所需状态/资源/取消边界成立；确有必须异步或委派的场景，先支持一种 | 超时与迟到结果有归属；不重复写；子任务不能越权或重置父预算；单Agent对照可说明是否值得 | 通用Agent群、所有Provider/远端恢复协议、同Session无界并发 |
| P6：证据驱动的系统级改进 | 已积累重复失败和稳定评测；先一个明确问题的隔离改进候选 | 原始复现、修后验证、退化和费用对照、独立保留样本；用户可决定采用或放弃，生产默认不变 | 自动升级权限、自动改生产Prompt/Schema/Memory、只优化已见Gold |
| P7：延期工具体系整理 | 所选版本主功能已收尾且用户决定启动，保持工具最后处理的优先级 | 用最少元数据替代名称前缀；副作用、风险、幂等/对账需求明确；改名不改变保护，旧工具有兼容说明 | 为架构漂亮重写全部工具/插件平台 |

P4—P6是原交接明确的长期方向，这里给出的批次边界和顺序是A建议的展开，不宣称过去已冻结。它们可因实际需求调整，但不能从总计划中消失，也不能被包装成P0/P2已经包含。

P1必须先做实际接口/调用链差异盘点；若已有能力已足够，仅补必要接线，不机械新开一轮实现。C/D可以共享一次设计与任务包，但C安全矩阵通过之前不能启用D执行。

### 三个交付里程碑

- **M1：可信任务闭环**：P0—P2，加P3必要演示。能观察、判断、有限纠错、再次验证。这里可以形成面试版本，但不是整个长期设计完成。
- **M2：可靠个人助手**：P3—P5中选定核心场景。Context、Memory、预算、长任务和协作按实际缺口改善，有日常可用性证据。
- **M3：可审计的持续改进**：P6的一个完整候选流程。任务级纠错与系统修改严格分开，采用仍由用户决定。

P7是延期的工具整理，不把它变为当前主线的前置；也不承诺没有终点的所有未来研究都结束后才允许做它。新入口若确需新增安全保护，单独明确最小边界，不借此提前全量重构。

## 5. 真实评测、研发成本和授权怎样安排

评测、隔离、安全和日志贯穿每个工作包，不是最后才补。最初交接中B后续还包含Artifact/Trace与远端副作用采集：先为选定场景提供足够证据；尚无权威对账保证的远端写入保留明确不支持范围，不声称B2完成了全部B后续。

真实模型收益验证在一个可用里程碑后单独安排，不必等P6全部结束。比较同一批输入与配置下启用/禁用某项机制的任务结果、成本、延迟和退化；请求数/费用/数据allowlist在执行前明确。离线机制、应用集成、真实任务收益分别报告；真实实验失败可以是NO_VERIFIED_GAIN或INCONCLUSIVE，不改历史成绩。

研发节奏：A一次说明问题、最小方案与必要判据；外部B整批实现；A集中复验。安全反例一批汇总，不按每个断言拆任务；没有新失败/变化，不重复全量。一般不足记账后收尾，不重新打开已完成阶段。

设计成熟度约60–70的含义是核心效果可用、必要检查通过、边界和后续方向清楚；不是只通过60–70%的安全测试，也不虚构成熟度分数。A不会承诺未测的固定工期或费用，外部编码harness费用与产品实验费用分开记录。

用户只需为范围/权限扩大、付费实验、真实用户数据、合入或发布作实质决策，不为普通实现细节反复审批。D启用前还需明确允许的纠错上限，以及原RFC的安全停止政策：真实安全风险可固定提示停止，但不泄漏隐藏原因；未获该执行政策批准仍只模拟。具体执行以最新授权为准。
