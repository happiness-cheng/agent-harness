# v0.2 冻结检索协议

本轮不调重要性权重。正式 Memory 写入/权限/确认/删除机制不变；卡片只在显式 `approved_fixture` 的离线适配器中构建。私人记录导入及模型/Judge 调用为 0。

## 数据与划分

- 原书 commit 和 60 题逐文件哈希冻结在 `reports/memory_v02/baseline.json`，保留原内容和原协议，不把新增组件实验冒称原书的模型任务测试。
- 原 8 道 Gold 题是诊断开发集，26 个表面事实组；沿用原 any-of 匹配，不计来源业务头。事实组总数以真实 JSON 计数为准。
- 其余 52 题按每层文件名顺序各选前 2 题。独立 6 题、23 个原始证据事实；Gold 在检索前固定，逐项带 conversation、消息索引、字符范围、原句哈希。由执行代理依据原始对话标注，不冒充用户审核、盲评或专家审校。不得拿本轮测试结果继续调参并声称泛化。
- 测试 Gold SHA256：`5771618d056d6e32b8635d32152079edaa3c7c784eb002964140fcb9dbcd6a5e`。运行器不接受变更后的 Gold。独立测试事实必须同时命中原文片段和该事实的来源证据，避免同金额在不同业务中碰巧相等。

## 三组固定配置

| 组 | 表示 | 检索 |
|---|---|---|
| A | v0.1 完整原始 Episode | 原有 Topic/FTS/图路径 |
| B | 原句 + 同会话前一句最多 600 字符 + 角色和业务标签 | 完全相同的 FTS/路由/融合函数 |
| C | B 同一卡片 | B 路径，加原文实体及显式 Name (ALIAS) 的精确词边界匹配；得分固定 1.0 |

Top-K=8、候选 cap=100、Topic top_g=3、上下文预算 2048 UTF-8 紧凑序列化字节。按 ID 融合后再截断；不会按文本合并不同会话。全部使用相同 owner 和历史，as_of 为最后会话时间 + 1 微秒；书中时间按会话粒度，缺时区沿用 UTC 假设。卡片的邻接信息只向前读取，不偷看未来消息或新会话。

卡片构建不读取问题、evaluation_criteria、Gold、模型输出。实体构建不接收 Gold，不外推别名；C 的结构化高分优先只是待测假设，不保证改进。

## 指标与边界

- Hit@8：至少一个必要事实出现在 Top-8；Fact Recall@8：必要事实组覆盖比例；MRR：首个覆盖任一事实项的倒数排名。均报告按题宏平均。
- 候选覆盖：分别报告 cap 后候选、cap 前全部实际融合候选、合法历史的事实覆盖。完整池的额外全局 FTS 探针只用于诊断，不改变最终检索。
- Top-8 与预算可见覆盖分别报告。上下文按排序装入整条，放不下就跳过，不补 Top-8 以外结果，不截断正文。预算不足不算作召回器失败。
- 错误情景：原 Gold 不足以计算全面语义错误率，标 NOT_RUN；另外报告跨情景同表面值碰撞提示，不能把碰撞数冒称错误率。合成安全测试另外验证明确场景隔离。特定例外原句覆盖另计，但不等于模型理解了例外。
- 成本：真实逻辑序列化字节（canonical、卡片 sidecar、索引输入）、请求上下文字节；非 SQLite 磁盘占用、非实际 tokenizer Token 数、非模型费用。
- 局部耗时：同进程每组每题 3 次普通检索的中位数，离线诊断时间不计；包括本实现重复构建内存 FTS 和读取权威状态的成本，不冒称线上延迟 SLA。
- 模型回答质量、Judge、Provider Token、真实任务成功率均 NOT_RUN。

## 停止规则

先完成合成契约测试，再固定代码哈希运行一次 14 题 A/B/C。失败和退化照实报告；不为了提高分数重改 Gold、删题或反复优化排序。只允许修复可独立复现的实现错误，并保留原运行证据。
