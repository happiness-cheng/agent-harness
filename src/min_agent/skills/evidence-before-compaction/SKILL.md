# 压缩前保留证据链

目标：压缩是有损的；证据链必须在压缩发生前落到不受压缩影响的位置，之后可回查。

## 步骤

1. **识别时机**：窗口接近软阈值、任务收尾、或即将切换阶段时，先做证据保全再整理上下文。
2. **落盘清单**：按 `references/evidence-checklist.md` 逐项核对——判据原文、测试命令与真实结果、
   失败证据、代码/配置版本（commit）、未完成事项。用 read_skill(name="evidence-before-compaction",
   path="references/evidence-checklist.md") 读取该清单。
3. **写对位置**：结论写仓库文档（状态页/工程日志），原始日志放受控位置；
   临时目录报告不能成为唯一交接信息。
4. **压缩后核对**：从落盘证据重建关键事实，不从压缩摘要推断「已验证」；
   摘要与原文冲突时以原文为准。

## 边界

- 历史失败证据保留，不删除、不改写；更正以追加方式写入。
- 本技能不改变压缩算法本身，只规定压缩前后的证据动作。
