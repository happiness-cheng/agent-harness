# 写测试先定判据

目标：测试是冻结的判据，不是实现的事后描述。先定判据，测试才有证伪能力。

## 步骤

1. **写场景卡**：每个测试先回答四件事——评价场景、测试输入、预期行为、判定标准；
   再加一条证据边界（这个测试证明不了什么）。
2. **区分样本**：开发迭代样本与固定验收样本分开；新反例另增回归样本，
   不修改原标准来让结果变好。
3. **先跑现状**：改动前先跑同一输入记录基线（通过/失败都如实记），改动后用相同判据对比。
4. **硬门不折价**：权限、隔离、事实真实性类断言失败就是失败，不用平均分或语气抵消。
5. **如实标注**：没运行的标 NOT RUN；程序测试通过不能证明自然语言效果，必要时写明范围。

## 边界

- 判据一旦冻结，修改判据本身需要显式记录理由，不属于「让测试通过」的常规操作。
- 小样本结果不声称总体成功率。
