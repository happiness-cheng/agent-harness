# Adrian 本地工作台

## 日常使用

1. 双击当前用户桌面的 **Adrian**。脚本使用本项目 `.venv`，启动现有 Python Runtime，并在服务身份及就绪检查通过后打开浏览器。
2. 默认访问 <http://127.0.0.1:8765/>。启动窗口需要保持运行。仅监听 `127.0.0.1`，不设置开机启动。
3. 新建或选择已有 Session，输入任务。普通任务仍走 `HarnessApplication → ManagedModel → Runtime`；不会切换到另一套实验后端。
4. **关闭：网页右上角“关闭服务”，等待服务窗口退出；或在服务窗口按 Ctrl+C。关闭浏览器不等于停止服务。** 停止任务与关闭整个服务是两个不同操作。

本机已创建的快捷方式：`C:\Users\陈独秀\Desktop\Adrian.lnk`。指向本项目 `scripts/start-adrian.cmd`，默认数据库仍为 `data/workspace.sqlite3`。

同一数据库由操作系统文件锁保护。再次启动相同配置时，只在工作区、数据库、实例标识、端口及运行模式均匹配后打开已有服务。其他程序占用端口、不同模式占用数据库时会报错，不会将其误认为 Adrian。不要通过删除锁文件绕过仍在运行的服务；进程退出后锁自动释放，残留文件本身不会阻止重启。此锁覆盖本项目网页启动入口，不能阻止第三方程序直接写 SQLite。

## 第一次配置

当前入口使用 **DeepSeek 官方 Responses、deepseek-flash、high**。启动只初始化客户端；发送任务后才可能产生模型费用。每进程原有最多 100 次模型请求的上限保留，Runtime 的任务及上下文预算也保留。没有请求成功与网络连通性的付费实测保证。

- 本项目需要 Python 3.13+ 与 `.venv\Scripts\python.exe`。新环境按 README 安装 `requirements.lock` 和本项目；不要用其他项目的 Python 代替。
- 凭据默认位于当前用户目录的 `agent-harness-credentials.json`，字段为 `deepseek_api_key`。真实值由用户在项目外配置，不放进脚本、快捷方式、日志或 Git。此轮没有修改凭据。
- 启动时通过当前 Provider 的只读 `GET /models` 获取并缓存所选型号的 `context_window` 与 `max_output_tokens`；此元数据请求不带对话或Memory，也不属于模型生成请求。拿不到合法能力数据时明确报错，不猜测32K、不切换Demo。上下文容量按模型返回值，生成输出预留按当前请求配置，两者与调用次数预算分开。主循环、压缩、Skill筛选与研究子循环复用该能力。当前输入计量是实际Provider请求体的保守UTF-8字节估计，并非精确Token计数；不会同时计算内部消息副本和原生续传状态。
- Adrian 快捷入口沿用本机代理 `http://127.0.0.1:7890`。请确认代理已运行；若不需要代理，可在启动前显式设置非敏感环境变量 `ADRIAN_PROXY=direct`。也可用 `ADRIAN_CREDENTIALS_FILE` 指向另一个项目外凭据文件。普通 CLI 入口不会隐式读取这些 Adrian 专用设置。
- 缺少虚拟环境、依赖或凭据会显示错误；不会暗中改为 Demo。代理配置成功也不代表外部网络可达。

移动工程后，可以在项目目录执行 `powershell -File scripts/create-adrian-shortcut.ps1` 重新创建本用户桌面快捷方式。脚本不修改执行策略；若系统策略禁止脚本，应遵循本机政策处理。遇到同名但指向其他程序的快捷方式会保留并报错。

高级启动选项可以传给 `scripts/start-adrian.cmd`，例如 `--port 8766`、`--no-browser`、`--no-long-memory`；需要与已经运行的服务配置一致。普通 `scripts/start.bat` 仍是离线 Demo，不读取凭据。

## 长期 Memory 怎么使用

Adrian 入口默认启用 **按需只读 Memory**；普通应用构造和 CLI 的原有默认行为保留。页面提供每 Session 的“长期 Memory”开关和情景范围，任务执行中不能改变这些设置。

启用后，已确认且当前合法的 Memory 主题索引进入动态上下文。模型可调用：

- `search_long_memory`：搜索合法历史，只返回 Memory ID。
- `read_long_memory_topic`：浏览合法主题索引，只返回 Memory ID。
- `read_long_memory_evidence`：请求读取已披露的 ID；正文经预算与权限校验后进入下一次实际模型请求。

明确提问示例：“请回忆我们之前确认过的项目约束，并标出记忆来源。”必须已有合法长期记录才有内容可回忆。没有记录时不能编造；此轮没有导入私人聊天或创建真实用户画像。

**启用表示允许把选中的已确认历史发送给当前配置的模型。** 原文保留来源、时间、情景及历史陈述性质；历史助手的话不因此变为实时核实结果。默认“通用情景”不自动读取专属情景的记忆；选择具体情景后才允许该情景内的合法记录，仍受 owner、确认、有效时间和撤回检查约束。历史文本不能授予工具权限，Plan/Build 与授权仍由 Runtime 执行。

本轮不自动提炼聊天、不自动保存长期记忆、不自动把推测写成用户画像。已有候选、用户确认、Goal / Scenario 生命周期及删除机制保持不变；页面没有新增完整的记忆录入编辑器。

### 送达和来源

状态详情区展示最近一次送达收据：

| 字段 | 含义 |
| --- | --- |
| requested | 工具明确请求读取的 ID |
| loaded | 已加载且校验合法的 ID |
| selected | 此次预算内选入投影的 ID |
| delivered | 实际 Provider 请求返回后确认送达的正文 ID |
| omitted | 因预算或当前不可用等原因未送达的 ID 与原因 |

调用异常记为 `delivery_unknown`，不会把准备好或读取过的证据冒称已送达。上下文中提供有界遗漏反馈；局部未找到、预算遗漏都不能证明完整历史不存在。

回答中的 `[memory:ID]` 可点击核对最近送达的来源。来源读取时再次检查当前合法性，撤回后不能继续获取正文。显式引用不在实际可见证据集合中时，回答不发布，任务按原失败路径停止；没有引用的普通回答仍允许。ID 校验只能证明引用范围，不能证明语义推理正确。

关闭 Memory 不会抹去模型或当前 Session 已见过的历史消息，也不代替原有删除/撤回流程。最新来源查看不是任意原文查询器，也不保证回查此前每一轮的引用。

## 故障排查

| 现象 | 处理 |
| --- | --- |
| `.venv` 或依赖缺失 | 按 README 安装当前项目环境；错误窗口保留，不会启动 Demo |
| 真实模型配置无法加载 | 核对项目外 JSON 字段及文件路径，不要把密钥粘贴到日志或仓库 |
| 无法核实当前模型上下文能力 | 检查本机代理、凭据及官方模型元数据接口；程序不会改用猜测窗口。恢复后重新启动 |
| 请求网络失败 | 检查本机代理、网络与模型账户；本次启动检查没有发送付费请求 |
| 端口被其他程序占用 | 先确认占用者，关闭正确程序或显式选择空闲端口；不会自动终止其他进程 |
| 数据库已有不同模式服务 | 先用原服务的关闭方式退出，再启动 Adrian；不要强行另开写库进程 |
| 浏览器未打开 | 确认服务窗口已显示就绪地址后手动访问；不能仅凭端口通就认定是 Adrian |
| 没有召回历史 | 检查 Memory 开关、情景、已确认记录及有效时间；此次没有自动导入旧聊天 |
| 伪引用导致任务失败 | 查看收据和实际送达来源；不自动增加模型调用修复引用 |

## 本次验证范围

无需数据库 Schema 迁移，沿用既有 Session SQLite 存储与长期 Memory 扩展。集成和网页交互使用 Mock/脚本模型、合成已确认记录验证；真实桌面入口确认到本地服务就绪、DeepSeek 客户端配置与 Memory active，模型请求计数为 0。

去重启动、关闭重启及 Session 数据保持在隔离数据库上实测。实际用户数据库的备份/重复启动组合检查被自动审批拦截，未执行；没有因此宣称完成真实库重启验收。完整回归仍有一项改动前即存在的长原文读取失败，详见本轮报告，不能称全量通过。

实验原始日志、前后版本清单及已知边界见 `reports/adrian-integration/summary.md`。此轮不默认启用新的排序实验，不推送远端。
